Reflex Adapt Classic2USB

Classic2USB is the RP2040-based Reflex Adapt model for connecting original game controllers to MiSTer, computers, and supported consoles over USB. Auto output defaults to XInput on Windows and DInput (the generic USB game-controller output) on MiSTer/generic hosts. Its firmware is built on RetroZord by Sonik (sonik-br).

All Reflex Adapt models

Firmware notes: firmware changes and hardware checks · controller hotkeys

2P Merge

2P Merge lets two controllers play as one player. Availability depends on the selected input family; see Mapping Basics for the related controller settings.

What you need

Classic2USB combines all supported controller inputs, USB output modes, OLED menus, settings, and utilities in one firmware image. Changing controller families or hosts normally does not require reflashing.

  • An original controller and its console-specific controller cable; see SNAC and Adapt controller adapters. The cable plugs into HDMI Port 1, the retro controller input port. The HDMI-shaped port carries controller signals, not video.
  • A USB data cable from the USB device port (the host connection for PC, console, MiSTer, and configuration) to the host. Charge-only cables will not work.

For MiSTer, the recommended starting point is Output = Auto with MiSTer Mode = DInput. DInput retains WebHID (browser access to USB HID devices; HID is the USB class for game controllers) for the device manager, serial management, and the MiSTer-specific controller identity.

Quick Settings and System Settings

Quick Settings hold controller-family preferences alongside Input/Output and global pointer controls. System Settings apply globally. See the settings reference for every option and submenu save behavior. Both menus use the same button commands.

Input and Output each open a list of modes: confirm one, then save the menu once to keep both choices. System Settings → Mode lists chooses which modes those lists show. A new or factory-reset unit opens a guided first-time setup, and System Settings → Setup guide replays it.

Button command Result
Reset tap Move down one row
Mode tap Change or confirm the selected item
Reset hold 1.5 seconds Discard all staged changes, exit, and show CANCELLED
Mode hold 1.5 seconds Save changes, exit, and show SAVED
Hold both buttons 1.5 seconds Open the guarded reset confirmation: Mode Defaults in Quick Settings, Factory Reset at the System Settings root; the chord is consumed inside System submenus and tools

Confirming RESET in Mode Defaults restores the active controller mode's defaults, saves them immediately, exits, and shows DEFAULTS RESTORED. CANCEL leaves the settings unchanged.

Confirming RESET in Factory Reset returns adapter and controller preferences, turbo and calibration to their defaults and restarts the adapter. A second prompt asks whether to KEEP or ERASE your button remaps; KEEP is the safe default. See Factory Reset.

In either reset confirmation, CANCEL is the safe default on the left and RESET is on the right. Reset taps move the selection; Mode confirms it.

Controller hotkeys

Current firmware uses fixed, controller/output-specific shortcuts, enabled together with System Settings → Hotkeys (On by default).

  • Start + Down sends Home, Guide or OSD.
  • Start + Left / Right / Up provide the controller's fixed extra actions. With Switch output, Left opens the NSO menu, Right sends Capture, and Up supplies Select where missing or X on the native NES/Genesis/N64 identities.
  • Capture / TPad is inactive in ordinary DInput/XInput PC and MiSTer output.
  • Custom shortcut assignments and Menu Hold are not available; use the adapter buttons to open menus.
  • Start a shortcut with exactly Start plus one cardinal direction and no other button. On Jaguar, Pause stands in for Start: Home is Down + Pause.

Kiosk Mode

Kiosk Mode is off by default. When enabled, it changes only the short front-panel actions:

  • Tap Mode twice to open Quick Settings.
  • Tap Reset twice to reboot.
  • Hold Mode for 1.5 seconds to open System Settings.
  • Hold Reset for 3 seconds to return Input and Output to Auto and restart detection; other settings are retained.
  • Menu holds still work: hold Reset 1.5 seconds to discard, Mode 1.5 seconds to save, or both 1.5 seconds for the guarded reset dialog at the menu root.
  • Holding Reset while connecting USB still enters the RP2040 bootloader.

Update firmware

Units without firmware

Early USA units ship without firmware flashed. Use the build and instructions supplied in the Classic2USB Discord group.

  1. Disconnect the adapter from USB.
  2. Hold the left Reset button while reconnecting USB.
  3. A removable RP2040 bootloader drive appears.
  4. Copy the Classic2USB UF2 supplied with those instructions to that drive. Do not use a generic Pico or Original image.
  5. Wait for the drive to eject and the adapter to reboot.
  6. Confirm that the Reflex home screen appears.

You can also connect in DInput and use the device manager to enter the bootloader before a manual UF2 copy.

Reflex Adapt Manager on MiSTer

Reflex Adapt Manager is the MiSTer script for firmware, recovery, settings, and mapping actions across the Reflex Adapt family. It detects the connected product and shows only the actions that apply. See Install Reflex Adapt Manager for installation and the mapping actions, and MiSTer setup and mapping for GameControllerDB, rumble, and official maps.

USB drive

In DInput and the MiSTer outputs, Classic2USB also appears as a read-only drive named CLASSIC2USB. It holds an offline guide, the official MiSTer maps with install_maps.sh and remove_maps.sh, and a copy of Reflex Adapt Manager with install_manager.sh. Console outputs never show it. The drive is On by default; if it changes the number MiSTer gives your own USB storage, turn System Settings → USB Drive Off. See the settings reference.

Troubleshooting

Classic2USB is not detected

  • Try a known-good USB data cable; charge-only cables will not work.
  • Connect directly to the host while testing.
  • Return Auto output's host preference to DInput using the OLED menu.
  • Hold Reset while connecting USB to confirm the RP2040 bootloader can still appear.

The unit has no firmware

Early USA units ship without firmware flashed, so the Reflex home screen does not appear until firmware is installed. Follow Update firmware with the build supplied in the Classic2USB Discord group.

The controller is not detected

  • Confirm the controller cable is connected to the intended input port.
  • Hold Reset for 3 seconds to return Input and Output to Auto and restart detection; other settings are retained.
  • Follow any assisted-detection prompt shown on the OLED.
  • Test the controller on original hardware when possible.

MiSTer receives the wrong buttons

  • Start with DInput and use MiSTer's normal input mapping menu.
  • Install missing official mappings through Reflex Adapt Manager.
  • Use Restore official mappings only when you intend to replace a changed official filename.
  • Remove stale duplicate mappings before creating another custom map.
  • To start over, Reflex Adapt Manager's Remove all Classic2USB mappings moves every Classic2USB map, including your own, into a dated folder so MiSTer uses its default mapping.

Management tools disappeared

WebHID and the serial interface are available in management-capable modes, normally DInput. Return the PC Mode or MiSTer Mode preference to DInput from the OLED menu.

Report a firmware problem

  • Record the input mode, output mode, host, controller model, firmware version, and exact reproduction steps.
  • Include a photo or video of the OLED when detection is involved.
  • Report problems in the Classic2USB Discord group, naming the firmware build you are using.

Classic2USB Quick Start

You need:

  • Classic2USB
  • A USB data cable. Charge-only cables will not work.
  • The controller cable for your console, and the controller
  • A computer for the first firmware install

Classic2USB has two buttons: Reset on the left and Mode on the right.

1. Plug in

Connect the USB cable from Classic2USB's USB device port to your computer.

  • The Reflex home screen appears: firmware is already installed. Step 2 is only needed to update it.
  • The screen stays blank and a drive named RPI-RP2 appears: the unit has no firmware yet. Early USA units ship this way. Continue with step 2.

On a Mac, a Linux PC or MiSTer, a read-only drive named CLASSIC2USB also appears once firmware is running. It holds an offline guide and MiSTer maps; it is not the firmware drive.

2. Flash firmware

Use the Classic2USB file

Use the Classic2USB .uf2 file from the Reflex Adapt releases. Do not use a Reflex Adapt Original or generic Raspberry Pi Pico file.

  1. Unplug Classic2USB.
  2. Hold Reset and plug the USB cable back in, then release Reset. A unit with no firmware does this without holding Reset.
  3. Copy the Classic2USB .uf2 file to the RPI-RP2 drive.
  4. The drive closes by itself and the adapter restarts. Wait for the Reflex home screen.

On a new or factory-reset unit, a short first-time setup then opens on the screen. Choose Guided setup for a practice tour of the two buttons and your basic preferences, finishing with Save and finish, or choose Skip to keep the current settings. Every choice can be changed later in System Settings, and System Settings → Setup guide replays it.

For later updates, the device manager can put the adapter into update mode for you. It connects only in DInput, so on Windows first set System Settings → PC Mode to DInput. On MiSTer, Reflex Adapt Manager installs released firmware.

3. Connect to the host

Plug Classic2USB into the system you will play on: MiSTer, a PC or a console. Connect it directly while setting up rather than through a hub.

Leave Output on Auto. The adapter identifies the host and picks an output for it. It can restart once while it does this; that is normal. A confirmed native mouse can instead select Mouse output on a suitable host; see Mouse output.

Host Auto picks
MiSTer or Linux DInput (System Settings → MiSTer Mode)
Windows XInput (System Settings → PC Mode)
Switch or Switch 2 Switch Pro
PlayStation 3 PS3
PlayStation 4 PS4, which needs your own authentication keys
Xbox 360 Xbox 360
Original Xbox Xbox Classic

On MiSTer keep MiSTer Mode on DInput, its default. DInput is the output MiSTer's controller database recognizes, and it keeps the device manager working. The output modes page covers every output.

4. Plug in the controller

  1. Plug the controller cable into HDMI Port 1. The HDMI-shaped port carries controller signals, not video. Use HDMI Port 2 for a second player.
  2. Plug the controller into the cable.
  3. Leave Input on Auto. Most controllers are recognized within about a second.

A few simple controllers cannot be told apart electrically. While the screen shows Assisted detect hold..., hold the button below until the controller is named:

Controller Hold
Atari 2600, C64 or SMS joystick Fire
MSX, FM Towns or X68000 A / 1
Neo Geo Start
Jaguar Pause

To switch to a different kind of controller, hold Reset for 3 seconds and Input and Output return to Auto and the adapter detects again; other settings are retained. After unplugging one of the controllers in the table above, tap Reset to restart before detecting again.

Tester firmware 1.1.x has a higher version number than the 1.0.0 release, so automatic newer-version offers will not downgrade it. To migrate, manually copy the release UF2 using the bootloader procedure above.

5. Check the input and output mode

The home screen shows the controller and the output on one line, as controller > output. The drawing under it shows each button as you press it.

  • On MiSTer the output should read DInput.
  • Press every button and move each stick to check the controller.
  • If the controller is wrong or missing, hold Reset for 3 seconds to return Input and Output to Auto and detect again; other settings are retained. To choose it yourself, tap Mode, open Input, pick the controller from the list and confirm it, then hold Mode to save.
  • To force an output, pick it from Output the same way.

7. Map controllers on MiSTer

  1. Run MiSTer Downloader or Update All to update the installed controller database, gamecontrollerdb.txt.
  2. Keep Output on Auto with MiSTer Mode on DInput.

Most controllers are then mapped automatically. MiSTer's controller database recognizes each Classic2USB input, and most cores need nothing more.

Five controllers need a custom map for their own core:

N64 N64 N64_input_16d0_1460_ReflexN64_v3.map

Jaguar Jaguar Jaguar_input_16d0_1460_ReflexJag_v3.map

Install them in any of three ways:

  • Reflex Adapt Manager: follow the installation steps in the Manager guide, then open Scripts → Reflex_Adapt → reflex_adapt_manager → MiSTer setup / mappings → Install missing Classic2USB mappings. Existing maps are preserved. Install Reflex Adapt Manager
  • From the adapter's drive: the read-only CLASSIC2USB drive carries the same maps, with install_maps.sh in its Scripts/Reflex_Adapt folder. Copy that folder to the SD card's Scripts folder, then run install_maps.sh from Scripts > Reflex_Adapt while the drive is connected. It keeps a .bak of any map you changed.
  • By hand: download the file and copy it to /media/fat/config/inputs/ on the MiSTer SD card.

A few cross-system pairings, such as a Genesis pad in the Saturn core, also have official maps. The core compatibility page lists every controller and core. For a neGcon, also set Pad 1 to Wheel-NegCon in the PSX core's menu.

If something goes wrong

  • The host does not see the adapter: try another USB data cable and connect directly to the host.
  • The controller is not detected: check that the cable is in HDMI Port 1, then hold Reset for 3 seconds.
  • MiSTer gets the wrong buttons: look in /media/fat/config/inputs/ for an old map for the same controller. A map file there overrides the database.
  • The adapter will not start: hold Reset while plugging in USB and flash the firmware again.

More help is in the product guide's troubleshooting.

Classic2USB How-To Guides

All of these start in Quick Settings: tap the Mode button on the home screen. A row appears only when the connected controller and output can use it. Your edits are not kept until you Save: choose Save on the bottom row, or hold the Mode button for 1.5 seconds. See Open, navigate and save.

Turbo

  1. Open Turbo. The page lists each button with its rate.
  2. Move to a button and change its value until you reach the rate you want.
  3. Choose Back, then Save.
Label Rate Latched label
Off No turbo
Slow 12.5 Hz Slow Latched
Med 15 Hz Med Latched
Fast 20 Hz Fast Latched
Max 30 Hz Max Latched
Ultra 60 Hz Ultra Latched

Plain rates repeat while you hold the button. A Latched rate starts on one press and stops on the next. Turbo follows the physical button, so a remapped button keeps its turbo.

Button Remap

  1. Open Button Remap. The page is titled Input > Output and each row reads button->host button.
  2. Move to a button and change its value until it shows the host button you want. A ! marks a changed row.
  3. Choose Back, then Save. Default restores this page's assignments.

The map is saved for this input and output pair, so a different output can use a different map. Several buttons can share one host button; it stays pressed until you release them all. See Button maps.

2P Merge

Two controllers play as one player, for example one for movement and one for buttons.

  1. Connect both controllers and open 2P Merge.
  2. Set Enabled to On.
  3. Set each control to P1 or P2.
  4. Choose Back, then Save. Changing Enabled can restart USB.

A control set to P2 is read only from controller 2, so pressing it on controller 1 does nothing. If the assigned controller is unplugged, that control stops working. Both controllers feel rumble from the host. The row is hidden for a connected neGcon, on Mouse output, and for INTV and Coleco.

Stick Cal

Use this when a stick cannot reach its full range. It is not available for N64, and it covers the first controller only.

  1. Open Analog, then Stick Cal. The page is titled Calibrate Stick.
  2. Move each stick around its full travel, into every edge.
  3. Select Save. Cancel leaves things as they were and Clear removes the saved calibration.
  4. Save Quick Settings as well, or the result is lost.

Where the Analog page has a Stick Range row, Save sets it to Cal, and Clear returns it to its default.

Analog Test

Use this to check centering and full travel. It changes nothing.

  1. Connect an analog controller.
  2. Open Analog, then Analog Test.
  3. Move the stick and watch the display. With two sticks, press Left or Right on the controller to switch between them.
  4. Press OK or Back to leave.

Other controllers show their own page: Wheel Test, neGcon Test or Paddle Test.

GunCon Align

This fine-tunes a connected GunCon. It does not replace the calibration in a game or core.

  1. Connect the GunCon and open GunCon Align. The page is titled GunCon Alignment.
  2. Press Left or Right on the controller to set X Alignment, from -50 to +50.
  3. Press OK, then set Y Alignment the same way.
  4. Press OK to reach Done, and OK again to leave.
  5. Save Quick Settings.

The row is hidden on MiSTer Paddle, MiSTer Spinner and Mouse output.

NES and Famicom Vaus

Untested

The Vaus reader has no hardware pass yet. The wiring below comes from the firmware's pin assignments.

The adapter cannot detect a Vaus, so you must select it. Each HDMI port takes one Vaus.

Wiring

Signal NES HDMI pin Famicom HDMI pin
Latch (starts a reading) 2 2
Knob clock 1 4
Knob data 6 7
Fire 5 3

The two versions use different pins and are not interchangeable. This table lists signals only. Power and ground are not covered here.

Setup

  1. Connect the Vaus and open Quick Settings.
  2. Set Input to NES.
  3. Set NES Device to Vaus NES or Vaus FC.
  4. Set Output to MiSTer Paddle, or an analog gamepad output such as DInput.
  5. Save, then adjust Rotary Gain and Reverse if needed.

Fire acts as the A button. A port set to Vaus can look connected with nothing plugged in. Knob range calibration and the Arkanoid II chained connection are not supported. Set NES Device back to Pad to use a normal controller.

Classic2USB Troubleshooting

First, read the home screen. It shows the input and the output in use. Most problems come from a mode set by hand, so returning to Auto fixes many of them.

On the adapter, Left is the Reset button and Right is the Mode button.

Get back to Auto

  1. Leave any menu, so the home screen is showing.
  2. Hold the Left device button for 3 seconds.
  3. The screen shows AUTO and Input+Output: Auto. Release the button and the adapter restarts.

Other settings are kept. This also works with Kiosk on. Inside a menu, the same hold cancels the menu instead.

The host does not see the adapter

  • Try another USB cable. Some cables only carry power.
  • Connect directly to the host, not through a hub.
  • If the OLED stays dark or the adapter will not start, hold Left while plugging in USB, then flash the firmware again.

The controller is not detected

  • Check that the cable is fully seated in an HDMI port, and try the other port.
  • Tap Left on the home screen to restart the adapter.
  • Return to Auto. A manual Input ignores other controller families.
  • If Auto still misses it, set Input to the controller's family by hand.
  • INTV and Coleco are manual only. Tick them in System Settings → Mode lists first. CD-i is hidden.

If it has never worked, try another controller of the same type. Then check Input modes for that controller's status.

The wrong input or output is showing

  • Input and Output are kept across firmware updates, so a manual choice stays until you change it.
  • On Windows, Auto uses PC Mode, which defaults to XInput. If you wanted DInput, change PC Mode, or set Output to DInput.
  • On MiSTer, Auto uses MiSTer Mode, which defaults to DInput. If the home screen shows another output, set Output to DInput by hand.
  • If an input or output is missing from the list, check System Settings → Mode lists.
  • After a change, reconnect USB if the host still shows the old controller.

See How Auto picks.

Buttons are wrong

  • Only one button is wrong: open Button Remap and look for rows marked !. Default restores the page.
  • The map changed with the output: remaps are saved per input and output pair.
  • A and B or X and Y are swapped: try Button Map, which switches between Name and Position where it applies.
  • Nothing makes sense: in Quick Settings, hold both adapter buttons for 1.5 seconds. This opens Mode Defaults for the current input family.
  • Start + a direction does something else: those are fixed shortcuts. Turn them off with System Settings → Hotkeys.
  • A button repeats: check Turbo. A Latched rate keeps running until the next press.
  • A control does nothing: check 2P Merge. A control set to P2 reads only controller 2.
  • A button seems ignored after a menu: release it. A button held while a menu closes stays off until you let go.
  • Sticks drift or fall short: use Analog Test, then Deadzone or Stick Cal.

No rumble

Rumble needs all of these:

  1. A controller with motors. That means DualShock or DualShock 2, an N64 Rumble Pak, a wired GameCube pad, or SNES RumbleTech hardware. WaveBird has none, and ordinary SNES pads have none even if the row appears.
  2. Rumble switched on. In Quick Settings, open Rumble and set it to Variable or Max, or On for a single motor. Test Heavy, Test Light or Test Motor runs the motor without the host, which rules out the controller.
  3. An output that carries it. Keyboard, Mouse, Remote and the MiSTer neGcon, Paddle, Spinner and GunCon outputs do not.
  4. A host that sends it. The game or core must request rumble.

On MiSTer with DInput, an older kernel can lack the driver support; see DInput rumble. XInput does not depend on it.

A console does not recognise it

  • Use a USB data cable, connected directly to the console.
  • Leave Output on Auto and reconnect. If that fails, set the output by hand; see Output by host.
  • Switch or Switch 2: turn on Pro Controller Wired Communication. On Switch it is under System Settings → Controllers and Sensors. On Switch 2 it is under System Settings → Controllers & Accessories.
  • Switch, NSO identity: test with Device set to Switch Pro. Report a failing identity along with your input controller.
  • PS4: the home screen shows PS4 NoAuth when no keys are stored. Upload your own keys; see PS4 notes.
  • Xbox 360: no key upload is needed.
  • Xbox One, Xbox Series or PS5: these are not supported.

Console outputs have no USB drive and no device manager connection. To use them, switch back to DInput.

Several consoles have no recorded test on this firmware. Choosing an output gives the status of each.

MiSTer mapping problems

  • Confirm the home screen shows the input you expect before opening a core.
  • Look in /media/fat/config/inputs/ for an old map for the same controller. A map there overrides the database.
  • Reconnect after changing input mode, so that MiSTer sees the new identity.
  • If the extra USB drive changes the number of your own USB storage, set System Settings → USB Drive to Off.

See MiSTer setup and mapping and Core compatibility.

Settings or firmware

  • After a firmware update: settings, Input and Output are all kept. The adapter shows Firmware updated for a few seconds at startup.
  • Reporting a problem: tester builds also report firmware 1.0.0 or 1.1.0. Include the Built date from System Settings → About.

  • Capture/TPad sends Capture in supported Switch output modes and a touchpad click in supported PlayStation output modes. It does not simulate touch coordinates or swipes.

  • It is not automatically a MiSTer screenshot shortcut.
  • Native NSO reports expose fewer controls than a full Pro controller. Unavailable actions show N/A and do not consume the chord.
  • A PS5-related report field in shared code is not PS5 console authentication. Classic2USB does not support native PS5 output; see the output reference.

Operation and safety

  • Start with exactly Start + one cardinal direction, with no other button held. A fresh diagonal is ambiguous and passes through rather than creating two shortcuts.
  • Once activated, keep Start and that direction held. Rolling onto a diagonal does not release the active shortcut; another action button ends it. A shortcut may duplicate a native physical button.
  • Host buttons remain pressed until the chord is released. LT/RT shortcuts send full digital pressure.
  • Menus own controller input while open. Release or disconnect clears generated actions; remap and turbo do not turn shortcuts into different host buttons.
  • Turning Hotkeys Off clears generated output and passes physical buttons through normally. Save System Settings to retain the global toggle.

Mapping Basics

Classic2USB normalizes controller input before sending it to the selected output mode. The output modes are DInput (a generic USB HID game controller; HID is the USB human-interface-device class), XInput (the Xbox 360 controller mode), and console-specific modes. Modes, player limits, host preferences, and rumble support are listed in the Classic2USB Output Reference.

Common per-mode settings include turbo, button remap, D-pad mode, and 2P Merge where the selected input family supports it. SOCD (simultaneous opposite cardinal directions) cleaning is always off; the setting is hidden and cannot be turned on.

Button Map = Name follows the controller's button names. Button Map = Position swaps Nintendo-style face-button positions where applicable, mainly A/B and X/Y.

Button remapping and turbo

  • The current remap view is labeled Input > Output: the left name is the physical controller input; the right name is its destination on the connected host.
  • Current firmware saves Button Remap per input family and output mode. Other controller preferences remain per input family; changing USB output can select a different remap profile.
  • Classic-controller turbo belongs to the physical source and runs before remapping. Moving that source to a different output moves its pulsed signal, not another button's turbo setting. Editing a remap does not reset the turbo rate.
  • Save the input-mode settings to retain changes after reboot. See the N64-specific assignment rules and Start shortcuts.

Native mice

Direct SNES, Saturn, Sega/Mega Drive, PlayStation, N64, 3DO, PC Engine and Dreamcast mouse input is preliminary, pending testing. Select Mouse output for relative movement and clicks. Auto input can identify these families; leave a PC Engine mouse stationary during discovery. Mouse layouts through multitaps or chains are not supported. Hardware coverage varies: SNES and Saturn have limited owner observations, while the newer paths and both-port behavior require further physical testing. Do not assume every mouse or host has been qualified.

Light guns

The GunCon is the only light gun Classic2USB supports. The NES Zapper, Super Scope and SMS Light Phaser are not supported: those guns read the display too close to the video timing to survive a USB conversion. Select the GunCon identity as described in MiSTer setup.

A GunCon needs a CRT, and MiSTer's own documentation notes that the Adapt path performs better than a GunCon 2 once MiSTer polls at 1 ms.

Enable 1 ms polling

MiSTer polls USB controllers more slowly until you ask for 1 ms (1000 Hz). Add this line to u-boot.txt in the linux folder of the MiSTer SD card (/media/fat/linux/u-boot.txt):

v=loglevel=4 usbhid.jspoll=1 xpad.cpoll=1

usbhid.jspoll=1 and xpad.cpoll=1 are what set the 1 ms rate. If the file already has a v= line, change it to match instead of adding a second one. Leave the existing ethaddr= line as it is: that value is the MiSTer's network address, not part of the polling change. Back up the file before editing it, and reboot for the change to take effect. A helper script can make the change for you: it removes only the old loglevel, usbhid.jspoll and xpad.cpoll values, adds the line above and keeps the rest of the file; see Enable 1 ms polling.

Calibrate in each core

Calibration is stored per core, so a gun calibrated in one core is not calibrated in another. The procedure is the same as the GunCon 2 procedure:

  1. Open the core you want to calibrate and display a full white screen. The 240p Test Suite's white screen pattern works well.
  2. Open the MiSTer OSD and press F10 on a keyboard. The light gun calibration dialog appears.
  3. Aim at each extreme edge in turn and register it, standing at the distance you actually play from.
  4. Aim for the widest numbers you can reach while the gun still sees the screen.

Do not save a crossed or negative calibration

Keep each axis's upper value above its lower value. If the two ends of one axis end up equal or crossed, MiSTer divides by zero when it applies the calibration and the core crashes. A negative value does the same. Recover by deleting that core's light gun calibration file from the config folder on the SD card, then calibrate again.

Non-zero upper and left values are normal. They are not an error to correct.

Sources: MiSTer light gun guidance and the GunCon2-MiSTer calibration instructions.

Classic2USB button maps for MiSTer cores

You plug an original controller into Classic2USB and play a MiSTer core. This page answers one question: when you press a button on that controller, which button does the core think you pressed?

These tables show the mappings Classic2USB intends. Some of their rows are still awaiting MiSTer's next GameControllerDB release, so until your MiSTer updates, those pairings can map differently. The core compatibility page says which rows are released.

The columns are MiSTer cores, the system being emulated, not Classic2USB output modes. The output modes, which decide what kind of USB controller the adapter looks like to the host, are on the output modes page.

Where the mapping comes from:

  • MiSTer identifies the adapter and looks it up in its GameControllerDB database.
  • If the database has a row written for the core you are running, that core's column follows it.
  • Otherwise the controller's generic row applies, and the core's own default button names decide where each button lands. MiSTer names its four face buttons like an SNES pad (B, A, Y, X), and each core gives those slots its own names.

What these tables leave out: D-pad directions, which always work, and the cores whose button names the firmware does not publish, among them N64, Saturn, Jaguar and Virtual Boy. Those pairings are on the core compatibility page, which covers every core. A dash (—) in a table below means the button lands on a slot that core does not use.

The input reference describes each controller family, and the MiSTer setup page explains how MiSTer selects the rows.

How Auto picks

  1. The adapter connects as a basic USB device and watches how the host talks to it.
  2. If the requests match Xbox 360, Xbox Classic, PS3, PS4, Switch or Switch 2, the adapter reconnects as that output.
  3. If they match Windows, it uses PC Mode.
  4. If nothing matches, it uses MiSTer Mode. This is what happens on MiSTer and Linux, so the adapter is not proving that the host is a MiSTer.

The home screen shows the result, for example Win XIn or MiSTer DIn. Output stays set to Auto, so detection runs again on the next start.

Two refinements apply after detection:

  • With DInput on a MiSTer or other generic host, a detected JogCon, neGcon or GunCon uses its MiSTer output.
  • A mouse-only input can select Mouse; see Mouse output.

A manual Output turns all of this off. Holding the Left device button for 3 seconds on the home screen returns Input and Output to Auto.

Mouse output

Select Output = Mouse, then Mouse Players = 1P or 2P in Quick Settings and Save. 1P uses physical port 1 only; 2P exposes independent mice on ports 1 and 2. The setting is saved per input mode and a changed count restarts USB. Use direct connections, not multitaps. MiSTer's ordinary USB mouse path combines mice into one stream, so use 1P there. MAME can distinguish two mice with -mouse -multimouse and per-game input assignments.

With Output Auto, a stable, driver-confirmed mouse-only input can select Mouse on Windows or a generic HID host after two seconds; a connected gamepad restores the host preference. Explicit output choices take priority. PC Engine mouse discovery requires the mouse to be stationary. Native mouse support and the different host paths still need hardware qualification; see the input reference.

PS2 Remote output

Remote is a 64-button USB joystick without axes, hat or keyboard/media commands. The captured PS2 remote maps 49 controls; application support for buttons above 32 varies. With PSX input and Auto or DInput output, choose PS2 Remote = Remote in System Settings or the contextual Quick Settings; Gamepad is the default. Selecting Output Remote directly also forces the persona. One receiver is exposed, preferring P1 when both are connected. A Windows P1 smoke test covered selected buttons, not every key or application. See PlayStation input.

Auto and the host preferences

  • Positively identified Windows and console hosts use their matching path.
  • MiSTer, Linux, and other generic USB hosts use the saved MiSTer Mode.
  • Windows uses PC Mode.
  • PC Mode defaults to XInput and MiSTer Mode to DInput.
  • Selecting a preference changes the output mode used after detection; it does not change the host-detection rules.

PC Mode and MiSTer Mode choose the output Auto uses after it detects the host. They are not the full manual output menu. The defaults suit most setups; change PC Mode to DInput only when a Windows tool needs DInput.

Xbox One/Series and native PS5 require authentication hardware Classic2USB does not have. PS4 keys do not make Classic2USB a native PS5 adapter.

Notes on individual modes

DInput. DInput rumble needs a host driver that supports it. On MiSTer the upstream Linux kernel includes it, but an older installed kernel can lack it; controls then work without rumble. See DInput rumble.

PS3. PS3 output uses the native wired DualShock 3 protocol. A directly connected DualShock 2 sends pressure for its twelve pressure-sensitive buttons; DualShock and digital pads send presses only, and pressure through a multitap is not supported. Set Rumble to Variable or Max to receive rumble from the host. Rumble in PS3 console games is still being checked.

PS4. Upload your key.pem, serial.txt and sig.bin key files with the device manager (Adapt.html), which is the only way to load them. Never publish or share personal authentication material.

Switch Pro. The NES, SNES, Genesis and N64 input modes offer optional NSO (Nintendo Switch Online controller) profiles in Quick Settings. N64 defaults to its NSO profile when Switch output is active; the others are opt-in.

Classic2USB MiSTer Setup and Mapping

DInput (DirectInput, the generic USB game-controller output) is the recommended starting mode on MiSTer. It preserves WebHID (browser access for the device manager), serial management, analog controls, and the input-mode-specific USB identity. Neither mapping nor management needs a USB drive.

The read-only USB Drive in System Settings is On by default. In DInput and the MiSTer outputs it adds a CLASSIC2USB disk with an offline guide, the official MiSTer maps with install_maps.sh, and a copy of Reflex Adapt Manager with install_manager.sh. Turn it Off if your own USB storage moves, because an extra USB disk can change MiSTer's mount numbering. See the settings reference.

Recommended setup

  1. Update MiSTer with Downloader or Update All, which keeps its GameControllerDB file current.
  2. Connect Classic2USB and leave Input = Auto.
  3. Set Output = Auto and MiSTer Mode = DInput, or select DInput manually.
  4. Complete MiSTer's main joystick definition once, when MiSTer asks for it.
  5. Use the official core map only when the controller/core pairing needs one; the core compatibility tables say which do.

How MiSTer mapping works

Classic2USB mapping has three layers:

  1. The firmware converts the physical controller into a shared neutral input frame without discarding controller-specific controls.
  2. DInput publishes stable HID (USB human interface device) buttons and axes plus a unique bcdDevice (USB device version) and product identity for the active input mode.
  3. MiSTer's GameControllerDB selects the matching input-mode row. A core-specific .map file can then provide a layout that the core cannot infer from the standard MiSTer/SNES-style controls.

GameControllerDB contains Classic2USB entries for every supported input mode, including separate core-specific rows where needed. Do not apply a blanket Nintendo A/B or X/Y swap: MiSTer names its common controls in SNES terms, while GameControllerDB entries translate each physical controller separately.

MiSTer's asysx and asysy are its system analog pair. GameControllerDB usually maps the primary stick to both leftx/lefty and asysx/asysy so cores using either convention receive the same movement.

GameControllerDB

  • MiSTer reads the Classic2USB rows from /media/fat/linux/gamecontrollerdb/gamecontrollerdb.txt, which is maintained outside the Reflex Adapt project and updated by the normal Downloader or Update All run. A matching row in gamecontrollerdb_user.txt in the same folder takes precedence. The core compatibility tables assume a MiSTer whose database includes the Classic2USB rows submitted in September 2026.
  • Every Classic2USB input mode uses the shared VID:PID (USB vendor and product IDs) plus an input-specific bcdDevice, allowing MiSTer to select the correct row.
  • Core-specific GameControllerDB rows handle many cross-system pairings without requiring a local .map file.
  • The OSD confirm and back buttons are set per input identity so the physical primary and secondary buttons behave naturally in the MiSTer OSD.
  • When a local map exists, MiSTer applies it after GameControllerDB.

Official core maps

These mapping files are supplied for the documented Classic2USB input identities. The core compatibility tables show which controller and core pairings need a file and list every official map with its download; those downloads are the complete, current set. Copy the required file to /media/fat/config/inputs/.

The USB Drive carries the same maps. Its Scripts/Reflex_Adapt/install_maps.sh copies them to /media/fat/config/inputs/ and first saves any existing map with different contents as <name>.bak. Copy the drive's Scripts/Reflex_Adapt folder to /media/fat/Scripts and run the script from Reflex_Adapt in the Scripts menu while the drive is connected, or run it from the drive over SSH.

Reflex Adapt Manager 0.5.0 and later carry the same ten maps. Install missing mappings adds any that are missing and never overwrites an existing file; Restore official mappings backs up and replaces changed official map files after you confirm. Run Downloader or Update All to bring an older Manager up to date first.

The DS2 analog and neGcon pad profiles require matching GameControllerDB entries. Use the supplied test database when validating this firmware candidate. Hardware acceptance of both profiles, and of mixed controllers, is pending.

Special PlayStation controllers

neGcon, JogCon and GunCon each have a dedicated MiSTer output:

  1. With Output = Auto and MiSTer Mode = DInput, Classic2USB switches to the matching MiSTer output when it detects one of these controllers on MiSTer.
  2. Otherwise, set Output in Quick Settings to MiSTer neGcon, MiSTer JogCon or MiSTer GunCon.

  3. Check the home screen: it shows MiSTer-nGc, MiSTer-Jog or MiSTer-Gun.

  4. neGcon: in the PSX core OSD, set Pad 1 = Wheel-NegCon. MiSTer reads the neGcon output as a wheel, and only that pad type reads both I and II as analog. USB identity and GameControllerDB mapping cannot change the core's emulated pad type. On this output I, II and L send pressure only by default; set I Button, II Button or L Button to Digital in Quick Settings when a core needs a button press instead. On DInput or MiSTer output a neGcon takes the neGcon pad profile instead.

  5. JogCon: select the JogCon mode you want in Classic2USB Quick Settings; the modes are in the input reference.
  6. GunCon: GameControllerDB includes validated mappings for the supported light-gun cores.

DInput rumble

Classic2USB's DInput rumble uses the same report format as the Google Stadia controller, so MiSTer's Stadia driver must recognize the Reflex VID:PID. The firmware side is complete.

  • The upstream MiSTer Linux kernel has included the Reflex IDs in its Stadia driver since September 2026.
  • An older installed kernel can lack them. DInput controls still work on it, but DInput rumble does not.
  • XInput (the Xbox-controller protocol) rumble uses Linux's XInput driver and does not depend on the Stadia-driver change.
  • GameCube, N64 Rumble Pak, DualShock/DualShock 2, and other supported rumble devices still depend on the selected core sending a force-feedback effect.

Core artwork on the OLED

Artwork-capable Classic2USB and MiSTer Serial builds can display Venice1200's i2c2oled core images. In a Manager build carrying Core Art setup / updates, use the setup action to rebuild existing artwork, or the download/update action to obtain the PIX collection. The initial conversion takes several minutes.

System Settings → MiSTer OLED → Artwork displays the core image across the whole OLED. Inputs displays normal controller feedback. A new core, game or changed artwork wakes the OLED and restarts the configured inactivity timer. Metadata and progress updates do not wake the OLED. The screensaver remains available between those events. Artwork has no title, player-label or loading overlay. Reload the core after rebuilding its image.

Troubleshooting mappings

  • Confirm the OLED shows the intended input mode before opening a core.
  • Remove or rename stale files for the same VID:PID and product identity.
  • Check /media/fat/config/inputs/ before creating a new map.
  • Let GameControllerDB provide the baseline, then add a core map only when the core-specific layout needs it.
  • If MiSTer loads the generic Classic2USB row instead of the input-specific identity, reconnect after changing input mode so USB can re-enumerate.

Adapt.html Device Manager

The device manager (Adapt.html) is a self-contained browser page for configuring and testing Classic2USB. No installation is required.

  • Open the device manager
  • Download Adapt.html for offline use
  • The hosted page is the Classic2USB-only app. Firmware builds remain separate.
  • Device communication runs locally between your browser and the USB adapter over WebHID (browser access to USB HID devices; HID is the USB class for game controllers). The memory-card tools and OLED preview also use Web Serial (browser access to the adapter's USB serial port). The website does not need an account or upload your settings, saves, or keys.
  • Use an Adapt.html version matching the firmware.

Browser requirements

  • Use current Chrome, Edge, or another Chromium browser with WebHID and Web Serial support.
  • Connect Classic2USB in DInput (DirectInput, the generic USB game-controller output).
  • Select Connect Device, then choose Reflex Adapt Classic2USB.
  • USB access requires your permission. The hosted site and an offline copy have separate permissions; choose the device again if prompted.
  • The first time you use the memory-card tools or OLED preview, the browser asks a second time: choose the adapter's serial port to allow Web Serial access.
  • Close other Adapt tabs or serial tools before connecting.
  • The page may contact GitHub only when checking for a firmware release.

Device Info and build matching

Open Device Info after connecting. Current firmware exposes the product, hardware target, unique unit ID and source/build identity. Include the build identity when reporting a problem; a shared version number alone may not distinguish tester builds. The current change notes identify the build they describe.

The manager is a separate tool from a firmware release. An empty stable update list does not mean the adapter is unidentified or faulty.

Firmware update

To update by hand, use the Bootloader command and copy the UF2 supplied with your build's instructions to the RP2040 boot drive, as in the quick start. The online steps below use the newest published release; an empty update list does not indicate a fault with your adapter.

  1. Connect Classic2USB to the device manager.
  2. Open Device Info and select Check Update.
  3. Review the detected product, installed version, release version, and release notes.
  4. Select Download UF2, then Choose UF2 file and pick that file. The device manager checks it against the hash GitHub publishes for it. Choosing a file also works with no internet, with a warning that no published hash was checked.
  5. Select Update Firmware and confirm.
  6. When the adapter restarts in its bootloader, tick the box that names your adapter and click Write to RPI-RP2 within 5 minutes. Select the RPI-RP2 drive in the browser's folder picker and allow it to write. Keep only that adapter in bootloader mode.
  7. If the browser cannot write to the drive, copy the UF2 to the RPI-RP2 drive yourself. Cancelling the picker retains the pending write.
  8. Keep the browser open and do not disconnect USB until the adapter reboots. The device manager confirms the new version when it reconnects.

The device manager accepts only a Classic2USB UF2. Check Update reads the official Reflex Adapt release, and the browser cannot download the file by itself, which is why you choose it.

Do not interrupt an update

Disconnecting power during the transfer can leave the adapter in recovery mode. Re-enter the RP2040 bootloader by holding the left Reset button while connecting USB, then copy a known-good Classic2USB UF2.

Controller Pak

The Controller Pak is the N64 memory card that plugs into the controller's accessory slot.

Property Value
Capacity 32 KB (128 pages of 256 bytes)
Common image formats .mpk, .n64, .bin
Individual note format .n64note (device manager export)

A Controller Pak holds its file table in pages 0-4 and game notes (saves) in pages 5-127. The device manager reads the note table, reports free and orphaned pages, and exports each note as a .n64note file that keeps the note's metadata and data pages so it can be restored later.

Device manager workflows

Workflow Behavior
Full-pak backup Read and download the full 32 KB image
Note export Export individual notes as .n64note
Note replace Replace an existing note after backup
Note delete Delete a note after backup
Note upload Import a .n64note

Write Safety

Before a replace, delete, or upload, the workflow backs up the data first. Changed pages are written through guarded transactions and then verified after the write. Keep the controller and Controller Pak connected until verification ends.

Transfer Pak

The Transfer Pak is the N64 accessory that holds a Game Boy or Game Boy Color cartridge. It plugs into the controller's accessory slot.

Property Value
Supported cartridges GB/GBC no-MBC, MBC1, MBC3, MBC5
Unsupported save RAM MBC2
Supported workflows GB/GBC save backup, save write, save erase

Classic2USB reads the cartridge header, reports the ROM and save sizes, and transfers save data in 32-byte blocks. The device manager does not dump cartridge ROMs.

Save uploads must match the cartridge-reported save size. The device manager backs up the existing save, stages the upload, writes whole 32-byte blocks, and verifies the changed data after commit.

Transfer Pak support is for GB/GBC cartridge ROM and external save RAM only. N64 cartridge EEPROM/SRAM/Flash saves are not connected to the controller accessory slot and are not reachable through this bridge.

Write Safety

All destructive VMU workflows use the same transaction order:

  1. Read card state.
  2. Back up the full card image.
  3. Back up the affected save when replacing or deleting.
  4. Work out which blocks change from the file table.
  5. Write the changed blocks through guarded transactions.
  6. Re-read changed blocks and compare bytes.
  7. Rescan card state.

Copy-protected saves are kept by default.

Stick Range and Rumble

Stick Range offers Raw, Norm, Cal, and Learn. Learn is the factory default: each stick axis and analog trigger begins at a conservative controller-family baseline and expands when a larger value is observed. Ordinary movement never shrinks a learned range. On GameCube controllers, the digital trigger click is also treated as proof of full travel, so a controller whose analog potentiometer tops out early can still fill the OLED gauge and output range correctly. Use Cal for a deliberate guided calibration, Norm for the fixed controller-family range, or Raw for unscaled values.

Variable-strength controllers expose Rumble: Off / Variable / Max in Quick Settings (tap the Mode button). Variable is the factory default and preserves the strength requested by the host independently for each motor. Max promotes every nonzero motor request to full strength while preserving which motor was requested; it is useful when a binary-era game or core produces effects too weak for a modern variable motor. Binary-rumble controllers continue to expose only Off / On.

MiSTer OLED Serial Display

In DInput mode, the USB serial port accepts MiSTer OLED display commands at 115200 baud. The firmware supports direct 128x64 SSD1306 frame updates and accepts common tty2oled-style commands for compatibility.

Limitations

  • WebHID (browser USB access for the device manager) and USB serial management are hidden only during active Auto probing. They become available once Auto resolves or when DInput is selected manually.
  • PS4 output requires user-provided auth keys.
  • Atari paddle controllers require different hardware.
  • PS2 IR Remote has Gamepad and 64-button Remote paths; selected buttons passed a Windows P1 smoke test on an earlier image. Further hardware and application testing remains open.
  • N64 Transfer Pak support does not access N64 cartridge EEPROM/SRAM/Flash saves.
  • MBC2 Transfer Pak save RAM is not supported.
  • PS3 output: one tester reported no DualShock 2 rumble in a game on a PS3 console, although the controller was recognized and its analog input worked. The cause is not known. Quick Settings > Rumble > Test Heavy / Test Light checks the controller's motors without the host.
